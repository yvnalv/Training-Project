# Security

## Threat model & posture

VialVision is a **single-device tool on a trusted LAN** (typically a Raspberry Pi
appliance). It has **no authentication, no accounts, and no multi-tenancy** by design
— anyone who can reach the device on the network can use it. Security work focuses on
transport (HTTPS for camera access) and safe handling of inputs and stored data, not
on access control.

> If VialVision is ever exposed beyond a trusted LAN, this posture is insufficient —
> add authentication and a properly trusted certificate first.

## HTTPS / TLS

- HTTPS is **required for browser camera access** (`getUserMedia` only works on
  secure origins or `localhost`).
- A **self-signed** certificate (`key.pem` / `cert.pem`) is generated by
  `generate_cert.py`. Browsers show a warning on first visit; the user accepts it
  once per device.
- The server is started with `--ssl-keyfile key.pem --ssl-certfile cert.pem`.
- The Pi autostart opens Chromium with `--ignore-certificate-errors` for the
  self-signed cert on the local appliance.

> The self-signed cert and its private key are committed in this repo for
> convenience on a private device. **Do not reuse these keys on any internet-facing
> or shared deployment** — regenerate per device and keep `key.pem` private.

## Input handling

- **Uploads (`/predict`):** images are read into memory and opened with Pillow; only
  the bytes are processed (inference + annotation). No filenames are executed or used
  as paths for reading; the stored filename is sanitized into a generated
  `timestamp_uuid.jpg` name on save.
- **Settings (`PUT /settings`):** only an allow-listed set of keys is persisted
  (`cameraMode`, `fps`, `resolution`, `confidence`, `flipHorizontal`); unknown keys
  are ignored. Invalid JSON → `400`.
- **WebSocket controls:** `resolution` and `set_conf` values are validated/clamped;
  bad values fall back to defaults.
- **SQL:** all queries are **parameterized** (`?` placeholders) — no string-built SQL
  with user data. The one dynamic fragment (the prune `IN (...)`) builds only
  placeholder counts, not values.

## Data at rest

- All data stays on the device: SQLite DB (`data/vialvision.db`) and annotated images
  (`data/results/`). No external services, no telemetry.
- History is capped at 500 records; older records and their images are pruned.
- There is no PII model; stored data is images of test racks plus derived MPN values.

## Network exposure

- The server binds `0.0.0.0:8000` — reachable from any host on the LAN.
- `_get_network_ip()` opens a UDP socket to `8.8.8.8:80` **without sending data**,
  purely to discover the primary interface IP for display. No outbound data leaves
  the device.

## Dependencies

- Pinned ranges in `requirements.txt` (FastAPI, Uvicorn, Ultralytics, Pillow, OpenCV
  headless, NumPy, websockets, python-multipart, jinja2).
- `opencv-python-headless` is used (no GUI libs) — smaller surface, appropriate for a
  server.
- Keep dependencies updated; the ML stack (Ultralytics/torch) is the largest surface.

## Hardening checklist (if exposing beyond LAN)

- [ ] Add authentication (reverse proxy basic-auth at minimum).
- [ ] Replace the self-signed cert with a trusted one (e.g. mkcert / internal CA).
- [ ] Bind to a specific interface or put behind a firewall.
- [ ] Rotate/secure `key.pem`; never commit a production private key.
- [ ] Add request size limits / rate limiting for `/predict`.
